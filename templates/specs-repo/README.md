# Спеки

Репозиторий артефактов: что и почему делаем, какие решения приняты, на что уже наступали. Код живёт в своих репозиториях — здесь только спеки.

## Структура

```none
TASKS.md          # индекс: папка → ID → статус
tasks/<папка>/    # одна единица работы = одна папка
```

Внутри папки задачи:

| Файл | Когда обязателен | Что внутри |
|---|---|---|
| `index.md` | всегда | статус, ID, репозитории, ветки, PR, скоуп, открытые вопросы |
| `decisions.md` | когда есть решения с альтернативами | журнал `D<n>`, текущая редакция |
| `problems.md` | когда наступали и обходили | журнал `P<n>`, текущая редакция |
| `notes.md` | пока идёт работа | черновики, карточка текущего пункта |
| `todo.md` | когда есть действия вне этапов | чекбоксы, до 15 пунктов |
| `spec.md` | когда требования надо согласовывать | что входит, что нет, критерии приёмки |
| `plan.md` | когда порядок работ неочевиден | карта этапов, чекбоксы |
| `analysis/` | когда собирали замеры, дампы или разбор кода | собранные данные, один файл — одна тема |
| `sources/` | нужны рабочие копии внешних документов | снапшот на дату; канон — в `../wiki` |
| `stages/NN-*.md` | когда этапов несколько | один файл на этап |

## Как этим пользоваться

- Начать с `TASKS.md`, если известен только ID. Иначе сразу `index.md` нужной папки.
- Нет файлов кроме `index.md` — это нормальный lite-режим, а не незаполненная спека.
- Всё остальное — процесс и правила записей — в скиллах `spec-driven-development` и `controlled-work` (репозиторий `spec-workflow`). Здесь структура, там смысл.

## Правила репозитория

- Папки задач не переименовывать и не перемещать: уточнения — в `aliases` внутри `index.md`.
- Один коммит — одно изменение: новое решение, новая проблема, закрытый этап, смена статуса.
- Заголовок коммита на английском, тело по-русски.
- Без `--amend`, rebase и squash: путь к решению — тоже артефакт.
- Секреты, пароли и внутренние адреса с доступами сюда не попадают.
- Одна задача — одна папка. Этапы одного проекта не разносить по папкам.
