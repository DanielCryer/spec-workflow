# Форматы записей

Правила для файлов внутри `tasks/<папка>/`. Структуру каталогов задаёт README репозитория спек; здесь — как писать содержимое.

## index.md

Единственный обязательный файл. Front-matter — машиночитаемые поля, тело — карточка.

```yaml
---
id: FRONT-9102          # фактический ID задачи в трекере
kind: project           # project | problem | research
status: active          # active | paused | done | dropped
mode: step              # quick | step | run — см. скилл controlled-work
repos: [core, api]      # имена репозиториев, пути — <PROJECTS_ROOT>/<name>
ref_roots: [../shared]  # дополнительные корни для ссылок файл:строка
aliases: [старое имя]   # прежние имена папки/задачи, для поиска
---
```

Поля `repos` и `ref_roots` читает гейт `scripts/spec_check.py`, поэтому имена — без путей, а разделитель — запятая.

В теле: «Скоуп» (что входит и что намеренно нет), «Открытые вопросы» (единственное место для них), «Итог» при закрытии, ссылки на ветки и PR. Решения по номерам здесь не перечислять — только сводные таблицы по теме.

## decisions.md

**Журнал — текущая редакция, не хроника.** Читатель должен понять правило сегодня, не восстанавливая историю.

Шапка файла:

```markdown
# Решения

**Последняя ревизия:** 2026-11-03
```

Ревизия — когда прошло больше недели (при активной работе 2–3 дня) или набежало больше 8 записей. Ревизия значит: перечитать, слить дубли, обновить статусы, а не переписать историю.

Запись:

```markdown
## D7. [этап][ID-подзадачи] Короткое имя решения

- **Контекст:** 1–2 строки, зачем вообще выбор. Без пересказа кода.
- **Решение:** что теперь считается правильным.
- **Альтернативы:** реально рассмотренные — с причиной отказа. Не было — `—`.
- **Последствия:** только «что теперь нельзя делать иначе». Без todo.
- **Статус:** действует
- **Ссылки:** repo@commit, файл, PR
```

Тело — до 12 строк, сведённая запись — до 18. `**Статус:**` — одно слово плюс от силы `(объединено с D4)` или `(заменено D9)`; подробности — в тексте.

Перед записью три вопроса: это выбор? альтернативы реально обсуждались? это не пересказ `spec.md` или кода и не следствие уже записанного решения? Хотя бы один «нет» — писать не сюда: требование → `spec.md`, «решим позже» → «Открытые вопросы» в `index.md`, набросок → `notes.md`, состояние кода и порядок работ → файл этапа, наступил и обошёл → `problems.md`.

Тест: «если завтра запись исчезнет — кто-нибудь сделает иначе?» Нет — не пишем.

Решили иначе — перепиши запись, прежнюю формулировку допиши в альтернативы: `— было (до 2026-10-01): …`. Устаревший факт (путь, имя, число) правь молча.

Нельзя: удалять нумерованную запись, переиспользовать номер, вычищать реально рассмотренные альтернативы. Решение влилось в другое — надгробие: заголовок, `— влито в D9`, `**Статус**: объединено с D9`.

Нумерация уникальна в пределах папки задачи и проверяется гейтом: повтор номера, номер вне индекса или ссылка на несуществующий `D<n>` — ошибка.

## problems.md

```markdown
## P3. Короткое имя проблемы

- **Симптом:** что видно.
- **Причина:** почему; неизвестна — так и писать.
- **Обход:** как обошли сейчас.
- **Остаток:** что осталось нерешённым.
- **Статус:** обойдено
- **Ссылки:** repo@commit, файл, issue
```

Нумерация и правила те же, что у решений. Проблема без «Остатка» — это не проблема, а заметка.

## notes.md

Черновик: не история, без номеров, правится и удаляется свободно. Здесь же живёт карточка текущего пункта в режиме `step` — предыдущая стирается, когда начинается следующий пункт. Доросло до решения — заводится `D<n>`, блок из `notes.md` вычищается. После закрытия этапа `notes.md` не держат.

## todo.md

Действия, которые не входят ни в один этап и не требуют ID. Чекбокс, строка, источник. Выполнил — удалил. Больше 15 пунктов — гейт предупреждает: это уже план, ему место в `plan.md`.

## spec.md, plan.md, stages/

- `spec.md` — требования, которые надо согласовывать: что входит, что нет, критерии приёмки.
- `plan.md` — карта этапов, когда порядок неочевиден. Пункты — чекбоксы `- [ ]`; отмеченный пункт обязан иметь коммит или тест.
- `stages/NN-*.md` — этап проекта, если их несколько. Один проект — одна папка, этапы внутри неё.

## Общие правила

- Даты — ISO `YYYY-MM-DD`.
- Факты из кода — со ссылкой: `<репозиторий>@<коммит>`, путь к файлу, при необходимости `файл:строка`.
- Один факт — один файл: открытые вопросы только в `index.md`, требования только в `spec.md`.
- Записи в проекте с этапами помечаются этапом, при необходимости — с ID подзадачи: `## D7. [codegen][FRONT-9102] …`.
- **Папки не переименовывать и не перемещать.** Уточнения — в `aliases`.
- **Историю не выдумывать.** Причина неизвестна — так и писать. Альтернатив не было — `—`, а не сочинённые варианты.
- Секреты, пароли и внутренние адреса с доступами в спеки не попадают.

## Закрытие задачи

- `index.md`: `status: done`, заполнен «Итог» — что сделали, чем закончилось, что осталось.
- Новые записи дописаны, статусы старых отражают реальность.
- `TASKS.md` обновлён.
- Вывод, полезный вне задачи, перенесён в вики.
