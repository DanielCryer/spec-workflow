# Controlled work: quick / step / run

Один процесс с тремя ритмами. Разница — где пауза, а не какие проверки.

| mode | как работает | пауза |
|---|---|---|
| `quick` | одна сессия, без спеки, гейта и ревьюера, тесты и коммит | в конце |
| `step` | цикл на один пункт: исполнитель → гейт → ревьюер → карточка | после каждого пункта |
| `run` | тот же цикл без пауз | только на серьёзном |

`step` — дефолт для задач со спекой. `run` — только по явной команде (`/run` или `mode: run` в `index.md`). Нет поля `mode` — значит `step`, нет папки спеки — `quick`. Уровень ставится один раз при заведении работы и меняется только по просьбе пользователя. Агент может один раз предложить повысить, но не переключает молча.

## Без спеки

Режим не обязан иметь спеку. Нет папки задачи — значит нет `index.md`, `notes.md`, гейта и карточки: `quick` работает как обычно, `run` идёт по плану из чата и отчитывается строкой на пункт в чате. Ревьюер подключается, если его явно попросили или задача трогает данные и безопасность. Всё остальное — те же правила остановки.

## Роли

- **Координатор** — главная сессия. Код не пишет: берёт пункт, отдаёт исполнителю, принимает вердикт, отмечает пункт, коммитит, пишет карточку. Свой контекст держит малым — иначе возвращается 200–300k.
- **Исполнитель** — субагент `general` на один пункт: цель, скоуп файлов, критерий готовности, запрет выходить за скоуп. Оставляет рабочее дерево изменённым и **не коммитит**: откат — это выброшенный дифф, а не revert. Прогоняет тесты и возвращает список файлов, команду с результатом и «не проверено».
- **Ревьюер** — субагент `spec-reviewer` со свежим контекстом. Ему передают только спеку, репозиторий и дифф, без обоснований исполнителя. Выдержки из спеки и дифф вставляй в запрос **текстом**: субагенту закрыт доступ за пределы рабочего каталога, и папку спеки он не прочитает. Модель ревьюера бери сильнее рабочей — иначе это самопроверка.
- **Гейт** — детерминированная проверка формы: `scripts/spec_check.py` из скилла `spec-driven-development` (base dir скилла выдаётся при загрузке). Запуск: `python3 <base>/scripts/spec_check.py --spec <папка>`, на Windows подойдёт `py`. Пути к репозиториям берёт из `repos:` в `index.md` и `PROJECTS_ROOT`, внешние корни для ссылок — из `ref_roots:`. Тесты не запускает: это работа исполнителя, а не проверка формы.

Точные формулировки задач исполнителю и ревьюеру, чек-лист качества тестов — `references/briefs.md`.

## Цикл (общий для `step` и `run`)

1. Взять первый неотмеченный пункт текущего этапа — порядок фиксированный, модель его не выбирает.
2. Исполнитель работает в своём контексте и прогоняет тесты.
3. Гейт (если есть спека).
4. Ревьюер.
5. `PASS` → пункт отмечен, коммит с `Spec:`, карточка (`step`) или строка в digest (`run`), следующий пункт.
6. `BLOCKED` → находки тому же исполнителю, всего до трёх кругов. Третий `BLOCKED` на одном пункте — стоп.

Где тесты не запускаются — это не «гейт не заметил», а незакрытая работа: без команды и результата пункт не считается готовым.

Круг считается по вердиктам на одном пункте: правки внутри круга не считаются, иначе координатор и исполнитель считают по-разному.

Если пункт на проверку больше шага — исполнитель возвращает «надо разбить», координатор дробит его на подпункты в том же плане и продолжает. Это механическая правка, не смена скоупа.

## Остановка — только серьёзное

- нужен выбор с реальными альтернативами — запись `D` в журнал;
- работа выходит за скоуп пункта или за репозиторий;
- гейт красный трижды на одном пункте или третий `BLOCKED` подряд;
- пункт противоречит спеке или допускает два прочтения;
- необратимое: переписать историю, удалить данные, тронуть станцию или прототип, отправить секрет;
- исчерпан бюджет прогона (пунктов или времени).

Механические выборы — имена, структура тестов, мелкий рефакторинг, порядок внутри пункта — решаются молча и попадают в коммит, а не в журнал.

## Карточка (`step`) и digest (`run`)

Карточка пишется в `notes.md` (переживает перезапуск, предыдущая стирается с началом следующего пункта) и показывается в чате. В ней: что сделано и какие коммиты, решения, принятые без пользователя, команда тестов с результатом, вердикт ревьюера и найденное гейтом, что сделает следующий пункт.

Строка тестов — обязательная часть карточки: `Тесты: <команда> → <результат>`. Без неё не видно, запускались ли тесты вообще, а гейт этого не проверяет. В `quick` та же строка идёт в отчёт о работе, в `run` — в строку закрытого пункта.

В `run` — строка на закрытый пункт, экран на закрытый этап. Без папки спеки и карточка, и digest живут только в чате.

## Остановился — что дальше

Короткий блок: «где встал / почему / варианты / что рекомендую». Ответ одной строкой продолжает прогон. Запись `D` в журнал ведёт координатор только после согласия пользователя. Набросок — в `notes.md`.

## Память

Состояние на диске: план, коммиты, журналы, карточка в `notes.md`. Обрыв контекста или перезапуск ничего не теряют — новый вход читает `index.md` → `plan.md` → `problems.md` и продолжает с первого неотмеченного пункта.
