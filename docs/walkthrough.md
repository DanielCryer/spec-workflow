# Одна задача целиком

Пример сквозной: вымышленный `BILL-42` — скидка на повторные заказы. Кода не показываем, только артефакты и то, что делает координатор.

## 1. Задача заводится папкой

Пользователь: «работаем по спекам, BILL-42 — скидки на повторные заказы». Агент загружает скилл `spec-driven-development`, читает `SPECS_ROOT/TASKS.md`, не находит BILL-42 и заводит папку.

`tasks/BILL-42/index.md`:

```markdown
---
id: BILL-42
kind: project
status: active
mode: step
repos: [billing]
ref_roots: []
aliases: []
---

# Скидки на повторные заказы

## Скоуп

Входит: расчёт скидки за второй и последующие заказы, отображение в корзине.
Не входит: акции и промокоды (PROMO-7), изменение тарифов доставки.

## Открытые вопросы

- Кумулятивная скидка считается за всё время или за 12 месяцев?
```

`TASKS.md` получает строку:

```markdown
| [`BILL-42`](tasks/BILL-42/index.md) | BILL-42 | project | active | 2026-11-03 |
```

Файлов, кроме `index.md`, пока нет — это lite-режим, и это нормально.

## 2. Первое решение

Обсудили кумулятивность и записали `decisions.md`:

```markdown
# Решения

**Последняя ревизия:** 2026-11-03

## Действующие решения

- **D1** — окно накопления: 12 месяцев, пересчёт по календарю заказа.

## D1. Окно накопления скидки — 12 месяцев

- **Контекст:** скидка за повторный заказ требует границы, иначе старые заказы влияют вечно.
- **Решение:** считаем по заказам за последние 12 месяцев от даты текущего заказа.
- **Альтернативы:** всё время — скидка растёт монотонно и её нельзя пересчитать задним числом;
  фиксированный порог в N заказов — не учитывает, что активность падает.
- **Последствия:** отчёт по скидкам зависит от даты заказа, а не только от суммы; пересчёт истории меняет результат.
- **Статус:** действует
- **Ссылки:** billing@a1b2c3d, `src/discount/window.py`
```

## 3. План

Пунктов получилось четыре — уже не lite, заводим `plan.md`:

```markdown
# План

## Этап 1. Расчёт

- [ ] Храним агрегат заказов за 12 месяцев: `src/discount/history.py`, тест на границу окна.
- [ ] Скидка по агрегату: `src/discount/policy.py`, тесты на 0/1/5 заказов.
- [ ] Отображение в корзине: `src/cart/view.py`.

## Этап 2. Наблюдаемость

- [ ] Метрика «скидка применена», чтобы видеть расхождение с бухгалтерией.
```

## 4. Один шаг в режиме `step`

**Задание исполнителю** (субагент `general`). Цель — первый пункт дословно. Скоуп — `src/discount/history.py` и его тесты. Критерий готовности — граница окна 12 месяцев проверяется тестом на заказ ровно год назад. Запрет — не трогать `policy.py`, не коммитить.

**Исполнитель** возвращает: изменённые файлы, команду тестов с результатом, «не проверено: часовые пояса».

**Гейт:**

```sh
python3 <base>/scripts/spec_check.py --spec $SPECS_ROOT/tasks/BILL-42
```

```text
0 error(s), 0 warning(s)
```

Тесты гейт не запускал — их прогнал исполнитель, команда и результат идут в карточку ниже.

**Ревьюер** получает выдержку из `plan.md`, `index.md`, путь к репозиторию и дифф текстом — без объяснений исполнителя. Ответ:

```text
BLOCKED
1. tests/test_history.py:31 — тест проходит и при пустой реализации: ассерт сравнивает
   результат с тем же вызовом. Грозит зелёным CI при отсутствии фильтра. Чинить: сравнить
   с ожидаемым числом заказов на границе.
что осталось непроверенным: часовые пояса, о которых предупредил исполнитель.
```

**Второй круг:** те же находки уходят исполнителю. Он правит тест, гейт снова зелёный, ревьюер отдаёт `PASS`. Третий круг понадобился бы, только если бы и вторая правка не сняла находку, — тогда координатор останавливается и переформулирует пункт.

**Карточка в `notes.md`** (её же координатор показывает в чате):

```markdown
## Шаг 1 — агрегат истории

Сделано: `src/discount/history.py`, окно 12 месяцев по календарю заказа.
Тесты: `pytest tests/test_history.py` → 12 passed.
Коммит: `[BILL-42] Add order history window`, Spec: tasks/BILL-42/.
Без пользователя решили: окно считается включительно по левой границе.
Ревью: BLOCKED (тест-заглушка) → PASS после правки.
Следующий пункт: скидка по агрегату.
```

**Коммит** в кодовом репозитории:

```text
[BILL-42] Add order history window

Spec: tasks/BILL-42/
```

## 5. Проблема по ходу

На втором пункте выяснилось, что бухгалтерия считает границу иначе. Это не решение, а наступили и обошли — `problems.md`:

```markdown
## P1. Граница окна расходится с бухгалтерией

- **Симптом:** расхождение в отчёте на заказах ровно годичной давности.
- **Причина:** бухгалтерия считает окно открытым справа, мы — закрытым слева.
- **Обход:** для отчёта применяем сдвиг на день, в расчёте скидки оставили как есть.
- **Остаток:** единая граница появится вместе с переездом отчётности (D3).
- **Статус:** обойдено
```
